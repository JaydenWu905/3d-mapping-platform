# 任务联动小车动画与已有成果切换：实施计划

日期：2026-10-18。本文是新计划，尚未据此修改任务链或实现预览切换。实施者不需要前序聊天上下文。

## 1. 最终目标

从网站正常入口创建演示任务，后台依次执行位姿估计、表面重建、距离场，每阶段约30秒。前端使用真实的任务状态和SSE进度驱动小车动画。阶段完成后有实际可加载的演示产物；用户可以在“当前任务动画”和“已有成果”之间切换。

必须支持：表面重建运行时查看已完成的位姿轨迹；距离场运行时查看位姿轨迹或表面网格。查看成果不能中断任务、改变进度或重新启动算法。演示产物明确标为合成示例，不冒充本次真实算法计算结果。

小车本身全自动：新一轮自动更换房间、路线起点与扫描方向，场景中没有点击、换房间、换方向或暂停按钮。页面层面的“动画/成果”切换是查看内容的选择，不是操控小车。

## 3. 第一阶段：修复任务演示链，优先完成

### 3.1 正确分流

- 在 `backend/app/services/runner_service.py` 统一判断是否需要真实表面输入准备。判断依据必须是服务端数据集注册的 `definition.execution` 和实际运行器选择。

- 真实MrHash任务继续执行原有时间基准、坐标语义、单位、四元数、文件完整性等校验。真实输入有问题时必须继续报错。

### 3.2 后台控制约30秒时长

- 修改 `backend/app/services/mock_runner.py` 的演示计时，三个阶段各约30秒，串行合计约90秒。
- 时长仅对mock运行器生效。可用服务端环境配置设为30秒，自动化单元测试使用短时长；不新增浏览器传入的任意时长字段。
- 进度通过既有 `progress.json`、REST快照及SSE更新；完成时按原流程复制已有演示产物并写结果清单。
- 前端不得另起计时器编造任务进度。真实算法耗时保持实际值，不强行设为30秒。
- 核查开始、完成、失败、取消和重试后的Job状态，确保不会进度100%却无清单，或阶段串行执行后状态回退。

### 3.3 明确任务身份

- 正常“新建任务”入口可选择演示数据集并一键运行三阶段。
- 根据现有 `GET /api/datasets` 的 `input_manifest.execution` 显示“演示任务 · 合成数据”；不能只依赖目前仅部分任务使用的 `preview_job` 标识。
- 产物来源沿用清单内的演示标记。实际算法任务按原入口和能力限制执行，不把演示成功当作真实算法验收。

## 4. 第二阶段：任务页加入动画与成果切换

预览区顶部加入两个直角选项：`当前任务动画`、`已有成果`。选择已有成果时显示可用阶段的选择器，未生成或未请求的成果不能被当作可预览项。

| 后台情况 | 当前任务动画 | 已有成果 |
| --- | --- | --- |
| 位姿运行 | 位姿小车，蓝色路线随进度展开 | 尚无成果时禁用并说明 |
| 表面运行，位姿已完成 | 表面小车，紫色网格随进度展开 | 可选择位姿轨迹 |
| 距离场运行，前两阶段完成 | 距离场小车，青蓝色块随进度展开 | 可选择位姿轨迹、表面网格 |
| 所有阶段完成 | 停止等待动画，默认显示最新可用成果 | 所有已生成的成果均可选择 |
| 后续阶段失败或取消 | 停动并显示真实状态 | 已完成且仍有效的前序成果继续可看 |

### 状态设计

- 将“后台当前执行阶段”“阶段详情选择”“预览模式”“成果阶段选择”分开管理，不能继续用一个 `selectedStage` 同时代表全部含义。
- `activeStageKey` 从服务端阶段状态派生；`previewMode` 记录动画或成果；`resultStageKey` 记录用户正在看的成果。现有阶段详情选择只负责详情、日志和明确的操作对象。
- 在预览区保留始终可见的简短执行提示，例如“后台正在执行：表面重建 42%”。查看位姿成果时该提示仍持续更新，避免误以为任务停止。
- 动画模式自动跟随实际正在运行的阶段。阶段间短暂交接显示准备状态，不把下一阶段提前动画成正在运行。
- 用户主动查看成果后，新进度或新成果到达不能抢走当前视图；只更新成果可用列表。点击“当前任务动画”才返回运行画面。
- 点击已完成阶段卡片可切入对应成果；点击运行阶段可回到该阶段动画。尚未开始、未请求或缺少产物的阶段显示相应说明，不播放虚假运行动画。
- 当前没有运行阶段且任务已结束时，停止动画并显示最新可用成果；完成但缺产物显示异常说明。失败/取消信息不能被已有成果遮住。
- 单次切换只改变本地预览状态，不发送启动、取消、重跑或修改请求。继续复用一个 `useJob` 和既有SSE连接。

### 产物判据与查看器

- 位姿：当前有效清单中存在 `trajectory_model`，复用 `TrajectoryViewer`。
- 表面：存在 `surface_model`，复用 `MeshViewer` 和既有预览URL/版本参数。
- 距离场：存在实际 `slice_xy/slice_xz/slice_yz` 中的可用项，复用 `EsdfViewer`。
- 不能只凭阶段100%或 `completed` 推断产物可用；文件加载失败时保留错误与重试反馈，不用小车覆盖失败。
- 上游重跑、任务切换后，失效的下游成果不能继续作为本轮成果显示。测试现有清理行为，如有缺口只作必要的状态/产物失效修复，不扩展成历史版本管理系统。
- 同时只挂载一个活动画布/三维查看器。切换时保持预览高度稳定，卸载时停止RAF、观察器和查看器资源。

- 取消、失败、重试、上游重跑造成的成果失效处理正确，不自动发起额外任务。
- 验证真实HTTP/SSE流程，不能只用前端时间线或拦截响应证明任务链跑通。

### 用户操作场景

1. 表面运行到中段，切到“已有成果→位姿轨迹”，轨迹实际加载；后台表面进度继续增长。
2. 切回“当前任务动画”，显示Surface当前进度，不重新从0开始、不换成另一间房间。
3. 距离场运行时，分别查看位姿轨迹和表面网格，再切回距离场小车。
4. 看成果时新的阶段完成，当前视图保持，新的成果入口变为可用。
5. 全部完成后能查看三种成果；后续失败时仍可查看已完成前序成果。
6. 20次预览切换后不积累Canvas、RAF、WebGL查看器、SSE连接；切换操作产生的变更型请求为0。
7. 1920×1080、1366×768、390宽与展示模式下不溢出、不重叠；保持Minimal UI配色、直角和清晰中文。

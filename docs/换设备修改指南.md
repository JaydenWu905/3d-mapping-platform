# 换设备修改指南

本平台当前可运行链路是 **ROS1 bag v2.0 → Livox `CustomMsg` + `sensor_msgs/Imu` → GLIM Pose → MrHash LiDAR Surface**。换话题、帧 ID、安装标定或 IMU 单位时，可新建独立设备配置。改成 PointCloud2、其他 Livox 结构或其他 IMU 消息格式时，需要一次性 reader/bridge 适配和测试；仅填写 JSON 不会使新格式可运行。

## 新增设备配置

1. 复制 [`self_capture_livox_custom.json.template`](../backend/config/upload_devices/self_capture_livox_custom.json.template) 为 `backend/config/upload_devices/<设备ID>.json`。文件名必须和 `id` 相同，例如 `my_livox_rig.json`。不要覆盖 [`ins_livox_mid360_same_rig.json`](../backend/config/upload_devices/ins_livox_mid360_same_rig.json)。原交接配置 [`ins_mid360_handoff.json`](../backend/config/upload_devices/ins_mid360_handoff.json) 原样保留供核对；运行时仅加载 schema v2、文件名与 ID 对应的配置。
2. 填写下表字段，更新 `version`，核对标定来源后设 `enabled: true`。上传页面按 ID 列出启用配置。每次上传的配置 SHA-256 和版本会固定在数据集注册记录中，上传过程中若服务器配置变更则拒绝登记。
3. 先将 [`ops/templates/device_runtime.json.example`](../ops/templates/device_runtime.json.example) 复制为本机 `ops/device_runtime.json`，按实际工作区相对路径填写。GLIM 配置文件位置在该本机文件 的 `glim_config_presets` 中按 `algorithms.glim.config_preset` 查找。ROS setup、解释器、库路径和 `MRHASH_ROOT` 仍由机器运行环境设置。设备配置里不写本机绝对路径。

| 字段 | 填写方式与来源 |
| --- | --- |
| `sensor.lidar.topic`, `sensor.imu.topic` | 本次 ROS1 bag 的实际话题；上传预检按这两个话题逐条验证，bridge 和 MrHash 读取同一选择。 |
| `sensor.*.message_type` | 目前必须分别是 `livox_ros_driver2/msg/CustomMsg` 和 `sensor_msgs/msg/Imu`。不匹配会在选择配置时明确报错。 |
| `sensor.*.frame_id` | bag 消息 header 的实际帧 ID；预检检查，bridge 发布时使用。例：`my_lidar_frame`、`my_imu_frame`。 |
| `calibration.T_lidar_imu` | 7 个数 `[tx, ty, tz, qx, qy, qz, qw]`，平移单位米；方向是 **IMU 坐标到 LiDAR 坐标** 的 `T_lidar_imu`。来自该安装的标定报告，不能照抄模板全零。 |
| `calibration.imu_acceleration_input_unit` | 从实际 IMU 消息确定 `g` 或 `m/s^2`；对应 `algorithms.glim.acc_scale` 分别为 `9.80665` 或 `1.0`。写明 `source`、状态、报告日期。 |
| `capture.imu_selection` | 写出 GLIM 实际使用的 IMU，尤其在 bag 含多个 IMU 时。选中的 `sensor.imu.topic` 必须对应它。 |
| `capture.*clock`, `point_offset_unit` | header 使用物理传感器时间；Livox `offset_time` 是相对 LiDAR header 的纳秒，bridge 转发 `t`；Surface 用 ROS bag record 时间，通过 98% 轨迹关联门限接续。若采集时钟语义不同，需要验证或适配。 |
| `preflight.*` | 逐点偏移、timebase/header 差、有效距离的 CPU 检查边界；单位分别为纳秒、纳秒、米。根据设备规格和采集证据填写，不用改程序常量。 |
| `algorithms.glim.*` | GLIM 的加速度、逐点时间参数；`config_preset` 是本机配置映射 ID。完整 GLIM 配置文件中的其他参数需另建配置目录和映射，不能在此声称已验证精度。 |
| `algorithms.mrhash.*` | 当前只接受已安装的 `livox_custom` reader、`ins_livox_mid360_custom` profile 与 `ins_livox_mid360.cfg`。话题来自 `sensor.lidar.topic`，不会强制 INS 话题。 |
| `camera.*` | 当前 LiDAR 链路不消费 RGB 或深度，两个 consumed 字段必须为 `false`；填写相机参数不会使 RGB-D 算法可运行。 |

单次采集的 bag 文件、SHA-256、大小、消息数和时间范围由上传与 CPU 预检记录到数据集 `input_manifest.preflight`、`sequence_observed`，不写进设备标定文件。每个新 Job 保存 `input/device_profile.json`、`input/effective_algorithm_params.json`，并在 `job.json.device_config` 记录 ID、版本、SHA-256 和快照路径。算法从该 Job 的输入快照读取参数，之后修改设备配置不会改变已有 Job。

## 何时需要代码适配

当前 bridge 仅反序列化 ROS1 Livox `CustomMsg`，将 `x/y/z/reflectivity/offset_time` 转成 ROS2 `PointCloud2`，并转发 `sensor_msgs/Imu`；CPU 预检和 MrHash Livox reader也针对这一结构。不同消息布局、字段单位、点时间语义、bag 格式或其他 IMU 类型，必须先增加相应 preflight、bridge、MrHash reader 支持和 CPU/真实设备验收。不同话题、帧 ID 与标定值且消息格式相同，可以新增配置再用新 bag 预检；配置通过不代表 GLIM/MrHash 建图精度已验收。

原始 INS 已验收数据集和历史 Job 保持原记录；同设备新序列仍使用 `ins_livox_mid360_same_rig`。新设备使用新 ID 和新标定，不能借用原 INS 的已验收状态。
